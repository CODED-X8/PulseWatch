Trade-off Explanation:
The simplified 5-second wait plus single fleet re-check probe is the optimal architectural
trade-off for production uptime monitoring:
1. False Positive Suppression: Network jitter, transient TCP handshake resets, and brief
   garbage collection pauses routinely fail single HTTP requests in distributed systems.
   Alerting on a single failed check causes engineer pager fatigue.
2. Minimal Alert Latency: Inserting a 5-second wait before a single fleet re-check probe
   trades only ~5 seconds of detection latency to ensure every alert is an actionable,
   confirmed failure.
3. Cost and Throughput Efficiency: Requiring 1 re-check probe instead of multiple iterations
   halves unnecessary SQS task messages, eliminates worker fleet re-check queuing delay,
   and prevents state machine execution thrashing.
